# V6.3 Rule Map

This is the converged rule view for testing V6.3. It does not add new behavior; it summarizes the current scaffold into a compact acceptance map.

Use this file when reviewing test outputs, comparing V6.2 and V6.3, or deciding which workflow node failed.

## RM-01 Core Contract

Must hold for every image:

- Edit the uploaded photo itself.
- Add only handwritten Chinese notes, doodles, arrows, frames, outlines, dotted lines, and subtle readability support.
- Preserve original filter, mood, visual proportion, composition, crop ratio, object positions, and identity.
- Generate exactly one result per input image by default.
- Process multiple images separately unless the user explicitly asks for a collage or merge.
- Retry at most once, and only for serious QA failure.

## RM-02 Required Diagnosis Meta

Before annotation planning, every image should have internal diagnosis meta:

- emotional line
- relationship summary
- subject mode
- key subjects or object groups
- high, medium, and low-priority objects
- scene state
- quiet/readability-safe areas
- uncertain professional objects that need conservative naming

This meta must pass forward to annotation strategy, prompt assembly, QA, and issue reporting.

Primary references:

- `photo-diagnosis.md`
- `SKILL.md` Photo Diagnosis
- `issue-report-template.md` IR-04

## RM-03 Emotion Comes From Scene State

Do not derive emotion from object names.

Correct:

- spilled drink -> small accident that needs reassurance and recovery
- person and dog outdoors -> shared play and outdoor lightness
- hiking gear flat lay -> preparation, order, safety, and departure readiness
- park kites -> sky, wind, city edge, watching people, and flying objects creating upward energy

Wrong:

- cup + keyboard + stain
- person + dog + grass
- backpack + clothes + tools
- many kites

## RM-04 Relationship First

Identify the main relationship before writing notes.

Common relationship types:

- person + pet
- person + object
- object + accident
- object + object
- scene + people
- sky/wind/light + subject

Annotations should support this relationship rather than label isolated objects.

Primary references:

- `photo-diagnosis.md` Relationship First
- `annotation-patterns.md` AP-02, AP-08
- `qa-checklist.md` QA-02

## RM-05 Subject Mode Controls Density

Classify subject mode before deciding annotation count.

- Single subject: usually 2-4 notes.
- Clear hierarchy: usually 3-5 notes, mostly around the strong subject.
- Portrait, pet, or landscape: usually 3-5 notes.
- Food spread, coffee table, tabletop collection, small objects, or travel street scene: usually 5-8 notes.
- Professional gear flat lay, packing checklist, or pre-departure equipment layout: usually 6-10 notes.

Density follows image intent, not object count alone.

Primary references:

- `photo-diagnosis.md` Subject Mode
- `annotation-patterns.md` AP-01
- `qa-checklist.md` QA-04

## RM-06 Collection Can Be The Subject

When the image is an intentional collection, the collection itself is the main subject.

Treat as collection subject when the image shows:

- gear arranged before departure
- food spread or drink table
- tabletop objects intentionally displayed
- packing, checklist, haul, workspace, toolkit, or flat lay
- professional preparation where each item has a role

Expected result:

- group related items
- use a gentle roll-call or "阅兵" feeling
- give important groups short functional-emotional notes
- stay readable even with higher density

- `photo-diagnosis.md` Collection As Subject
- `annotation-patterns.md` AP-05

## RM-07 Atmosphere Can Be The Subject

When no single object dominates, the atmosphere itself can be the main subject.

Treat as atmosphere subject when the image shows:

- quiet street corner, storefront, window, alley, or cafe exterior
- harbor, road, mountain distance, waterline, sky, dusk, rain, or strong light-and-shadow
- wide travel scenes where the place carries the emotion more than any object

Expected result:

- identify atmosphere carriers such as light, shadow, wind, air, distance, horizon, water, road, window, awning, sign, or color temperature
- use sparse notes, usually 2-4
- preserve negative space
- avoid object labels, travel-guide copy, storefront promotion, and generic landscape praise

Primary references:

- `photo-diagnosis.md` Atmosphere As Subject
- `annotation-patterns.md` AP-10

## RM-08 Low-Priority Props Stay Quiet

Visible does not mean worth annotating.

Low-priority props include:

- spoon
- mat
- ordinary equipment
- wall
- edge decoration
- generic background item
- tiny accessory without story

They may support the subject but should not become standalone protagonists.

- `photo-diagnosis.md` Object Priority

## RM-09 Small Accident Comfort

Small accidents should follow this emotional sequence:

```text
acknowledge the accident
  -> comfort the viewer
  -> add a light sense of recovery
```

Do not make embarrassment, failure, blame, or cleanup tutorial the main emotion.

Primary references:

- `annotation-patterns.md` AP-04
- `qa-checklist.md` QA-09

## RM-10 Doodles Express Relationships

Hand-drawn marks should serve the relationship or reading path.

Examples:

- person + pet: motion curves, attention lines, path lines, light hearts
- gear roll-call: outlines, group frames, dotted borders, check marks, route lines
- small accident: soft circles, gentle arrows, protective outlines
- park/kite/open sky: flight lines, wind paths, tiny stars, cloud bubbles
- food/drink: steam, cup-rim lines, small satisfaction marks

Avoid random decorative doodles.

Primary references:

- `annotation-patterns.md` AP-08
- `style-dna.md` SD-04, SD-05

## RM-11 Readability Without UI Cards

Text must be readable at social-media size, but readability support must stay light.

Allowed:

- better placement
- arrows from quiet areas back to the subject
- soft shadow
- thin outline
- subtle breathing edge

Avoid:

- heavy UI cards
- label blocks
- presentation tags
- strong sticker-like backing

Primary references:

- `style-dna.md` SD-03, SD-06
- `qa-checklist.md` QA-05
- `bad-cases.md` BC-09

## RM-12 Copy Quality And De-Duplication

Notes should be:

- Chinese-first
- short
- warm
- conversational
- specific to the current scene
- varied within the same image

Before generation, avoid repeated verbs, adjectives, sentence templates, and near-duplicate meanings.

Primary references:

- `annotation-patterns.md` AP-03, AP-07
- `qa-checklist.md` QA-07
- `bad-cases.md` BC-02, BC-07

## RM-13 Organic Handwriting, Not Font Text

The annotation layer must look hand-drawn, not font-rendered.

Failure signals:

- system-font Chinese
- subtitle-like text
- UI or presentation caption feeling
- uniform baseline and stroke width
- typed text with artificial jitter
- local PIL/ImageFont/font-path overlay used as a preservation repair

Correct response:

- treat this as serious QA failure
- retry image editing from the original photo at most once
- do not pass the local font overlay just because preservation checks look acceptable

- `style-dna.md` SD-02

## RM-14 Professional Naming

Professional scenes should feel understood but not overclaimed.

Use confident names only when confident. Otherwise use safer generic names.

Avoid:

- invented exact model names
- invented technical functions
- long equipment explanations
- gear manual tone

Primary references:

- `photo-diagnosis.md` Professional Scenes
- `qa-checklist.md` QA-08
- `bad-cases.md` BC-11

## RM-15 Example Calibration

Examples are calibration assets only.

Use examples to learn:

- relationship-first judgment
- scene-state emotion
- collection roll-call
- small accident comfort
- density and readability expectations

Never copy:

- composition
- object choices
- annotation text
- arrows
- frames
- flight lines
- hearts, stars, or other doodles

## RM-16 QA Retry Gate

Only serious QA failure can trigger one retry.

Serious failures include:

- original photo was redrawn, changed, visibly cropped, stretched, padded, or restyled
- aspect ratio, crop, subject positions, or visual proportion changed noticeably
- main subject changed
- annotations are unreadable
- low-priority props stole focus
- image is overcrowded
- wording repeats badly
- annotations look like system-font, subtitle, UI, or font-rendered fake handwriting
- professional objects were confidently misnamed
- small accident became mockery or cold labels
- collection subject was missed
- atmosphere subject became object labels or over-annotated travel postcard

Retry exactly once at most. Do not generate multiple options just to offer choice.

- `SKILL.md` QA Reflection

## RM-17 Issue Meta For Traceback

When the user says `report to issue:`, include workflow meta when available:

- photo diagnosis meta
- annotation strategy meta
- prompt assembly meta
- QA meta
- bad-case IDs
- example calibration meta
- expected vs actual behavior

If metadata was not captured, write `not captured` rather than inventing it.

## Test Acceptance View

For the first V6.3 test pass, review each image with this short checklist:

1. Was the original photo preserved?
2. Is there one emotional line?
3. Did the output understand the main relationship or scene state?
4. Did subject mode control density correctly?
5. If atmosphere is the subject, did the notes preserve quietness and space?
6. Did low-priority props stay quiet?
7. Are notes readable without UI-card styling?
8. Do doodles express relationships?
9. Is wording warm, specific, and non-repetitive?
10. Does the handwriting look organic rather than font-rendered?
11. Did QA catch serious failures?
12. If an issue is reported, can the failed node be traced?
